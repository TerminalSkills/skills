## The Problem

Juri is building the backend for a SaaS project. The typical Node.js stack — Express + Prisma + manual type definitions — works but has gaps. Express routes have no type safety: a typo in the response shape causes a runtime error that only surfaces in production. The client team writes their own TypeScript interfaces that drift from the server. Every layer has its own type definition, and keeping them in sync is a full-time job nobody signed up for.

Juri wants one source of truth: define the database schema in TypeScript, have the API types inferred from it, and have the client discover the exact request/response shapes. No codegen, no OpenAPI spec to maintain, no separate type packages.

## The Solution

Use **elysia** on Bun for the HTTP layer; it infers API types from route definitions. Use **drizzle-orm** for the database: schema in TypeScript, SQL migrations generated by drizzle-kit. Use **test-generator** to cover the routes with tests. The type chain: Drizzle schema → Drizzle queries → Elysia route handlers → Eden Treaty client.

## Step-by-Step Walkthrough

### Step 1: Project Setup

```bash
bun init my-api && cd my-api
bun add elysia @elysia/cors @elysia/jwt @elysia/openapi @elysia/eden
bun add drizzle-orm@0.45 postgres
bun add -d drizzle-kit@0.31 @types/bun
```

Elysia's docs install plugins from the `@elysia/*` scope; the older `@elysiajs/*` names still exist, but `@elysiajs/swagger` is deprecated in favour of `@elysia/openapi`. `drizzle-orm` (runtime) and `drizzle-kit` (migration CLI) are separate packages. A 1.0 release candidate of Drizzle exists on the `rc` tag and changes the relational API, so pin the stable 0.45 / 0.31 lines.

```typescript
// drizzle.config.ts
import { defineConfig } from "drizzle-kit";

export default defineConfig({
  dialect: "postgresql",
  schema: "./src/db/schema.ts",
  out: "./drizzle",
  dbCredentials: { url: process.env.DATABASE_URL! },
});
```

### Step 2: Define the Database Schema

The schema is the single source of truth. Every type in the application traces back to these table definitions.

```typescript
// src/db/schema.ts
import { pgTable, uuid, text, timestamp, boolean, integer, pgEnum, index } from "drizzle-orm/pg-core";
import { relations } from "drizzle-orm";

export const roleEnum = pgEnum("role", ["user", "admin"]);
export const users = pgTable("users", {
  id: uuid("id").primaryKey().defaultRandom(),
  email: text("email").notNull().unique(), // the unique constraint creates its own index
  name: text("name").notNull(),
  role: roleEnum("role").default("user").notNull(),
  passwordHash: text("password_hash").notNull(),
  createdAt: timestamp("created_at").defaultNow().notNull(),
});

export const projects = pgTable("projects", {
  id: uuid("id").primaryKey().defaultRandom(),
  name: text("name").notNull(),
  description: text("description"),
  ownerId: uuid("owner_id").notNull().references(() => users.id, { onDelete: "cascade" }),
  isPublic: boolean("is_public").default(false).notNull(),
  starCount: integer("star_count").default(0).notNull(),
  createdAt: timestamp("created_at").defaultNow().notNull(),
  updatedAt: timestamp("updated_at").defaultNow().$onUpdate(() => new Date()).notNull(),
}, (t) => [index("projects_owner_idx").on(t.ownerId)]);

export const usersRelations = relations(users, ({ many }) => ({ projects: many(projects) }));
export const projectsRelations = relations(projects, ({ one }) => ({
  owner: one(users, { fields: [projects.ownerId], references: [users.id] }),
}));

// Types are inferred from the tables, never written by hand
export type User = typeof users.$inferSelect;
export type Project = typeof projects.$inferSelect;
```

### Step 4: Build the API with Elysia

The app is exported from `src/app.ts` without calling `listen`, so tests and the Eden client can import it; `src/index.ts` starts the server.

```typescript
// src/app.ts
import { Elysia, t } from "elysia";
import { cors } from "@elysia/cors";
import { openapi } from "@elysia/openapi";
import { jwt } from "@elysia/jwt";
import { desc, eq, or } from "drizzle-orm";
import { db } from "./db";
import { users, projects } from "./db/schema";

const secret = process.env.JWT_SECRET;
if (!secret || secret.length < 32) throw new Error("JWT_SECRET must be set (at least 32 characters)");

export const app = new Elysia()
  .use(cors({ origin: process.env.CORS_ORIGIN ?? false })) // one named origin, never "*" with auth headers
  .use(openapi({ documentation: { info: { title: "My SaaS API", version: "1.0.0" } } })) // Scalar UI at /openapi
  .use(jwt({ name: "jwt", secret, exp: "7d" }))
  // resolve runs after validation (derive runs before it); `user` is available in every route below
  .resolve(async ({ jwt, headers }) => {
    const token = headers.authorization?.replace(/^Bearer /, "");
    if (!token) return { user: null };
    const payload = await jwt.verify(token); // false when the signature or expiry is invalid
    if (!payload || typeof payload.id !== "string") return { user: null };
    return { user: { id: payload.id, role: payload.role as "user" | "admin" } };
  })
  .post("/auth/register", async ({ body, jwt, status }) => {
    const passwordHash = await Bun.password.hash(body.password); // argon2id by default
    const [user] = await db.insert(users)
      .values({ email: body.email.toLowerCase(), name: body.name, passwordHash })
      .onConflictDoNothing({ target: users.email })
      .returning({ id: users.id, email: users.email, name: users.name, role: users.role });
    if (!user) return status(409, { message: "Email already registered" });
    return { user, token: await jwt.sign({ id: user.id, role: user.role }) };
  }, {
    body: t.Object({
      email: t.String({ format: "email" }),
      name: t.String({ minLength: 2 }),
      password: t.String({ minLength: 8, maxLength: 128 }),
    }),
  })
  .post("/auth/login", async ({ body, jwt, status }) => {
    const [user] = await db.select().from(users).where(eq(users.email, body.email.toLowerCase())).limit(1);
    if (!user || !(await Bun.password.verify(body.password, user.passwordHash))) {
      return status(401, { message: "Invalid credentials" });
    }
    return { token: await jwt.sign({ id: user.id, role: user.role }) };
  }, {
    body: t.Object({ email: t.String({ format: "email" }), password: t.String({ maxLength: 128 }) }),
  })

  // Public projects for everyone; the caller's own private projects too when signed in
  .get("/projects", async ({ query, user }) => {
    const visible = query.public || !user
      ? eq(projects.isPublic, true)
      : or(eq(projects.isPublic, true), eq(projects.ownerId, user.id));
    const rows = await db.query.projects.findMany({
      where: visible,
      with: { owner: { columns: { id: true, name: true } } },
      orderBy: [desc(projects.createdAt), desc(projects.id)],
      limit: query.limit,
      offset: (query.page - 1) * query.limit,
    });
    return { projects: rows, page: query.page, limit: query.limit };
  }, {
    query: t.Object({
      page: t.Number({ default: 1, minimum: 1 }),
      limit: t.Number({ default: 20, minimum: 1, maximum: 100 }),
      public: t.Optional(t.Boolean()),
    }),
  })

  .post("/projects", async ({ body, user, status }) => {
    if (!user) return status(401, { message: "Authentication required" });
    const [project] = await db.insert(projects).values({ ...body, ownerId: user.id }).returning();
    return project;
  }, {
    body: t.Object({
      name: t.String({ minLength: 1, maxLength: 100 }),
      description: t.Optional(t.String({ maxLength: 1000 })),
      isPublic: t.Optional(t.Boolean()),
    }),
  })

  .get("/projects/:id", async ({ params, user, status }) => {
    const project = await db.query.projects.findFirst({
      where: eq(projects.id, params.id),
      with: { owner: { columns: { id: true, name: true } } },
    });
    // a private project looks the same as a missing one to everybody except its owner
    if (!project || (!project.isPublic && project.ownerId !== user?.id)) {
      return status(404, { message: "Project not found" });
    }
    return project;
  }, {
    params: t.Object({ id: t.String({ format: "uuid" }) }),
  });

export type App = typeof app; // the type Eden Treaty reads on the client
```

```typescript
// src/index.ts
import { app } from "./app";
app.listen({ hostname: "127.0.0.1", port: Number(process.env.PORT ?? 3000) });
```

Return `status(code, body)` rather than the old `error()` helper: it is typed against the route's responses and Eden narrows on it. Bind to `127.0.0.1` during development and put a reverse proxy in front for production. Never return `passwordHash` or owner emails; the queries above select only the columns the client needs.

### Step 5: A Type-Safe Client with Eden Treaty

```typescript
// client/api.ts
import { treaty } from "@elysia/eden";
import type { App } from "../src/app";

export const api = treaty<App>(process.env.API_URL ?? "127.0.0.1:3000");

export async function demo() {
  // Every call returns { data, error }; error is a typed union of the route's status() responses
  const { data: auth, error } = await api.auth.register.post({
    email: "juri@example.com", name: "Juri", password: process.env.DEMO_PASSWORD!,
  });
  if (error) throw new Error(`register failed: ${error.status}`);
  const headers = { authorization: `Bearer ${auth.token}` };

  const { data: created } = await api.projects.post(
    { name: "My Project", description: "Built with Elysia + Drizzle", isPublic: true }, { headers });
  if (!created || !("id" in created)) throw new Error("create failed");
  console.log(created.name); // typed from the Drizzle schema
}
```

Change a route's body or response on the server and this file stops compiling until it is updated. Run `bunx tsc --noEmit` in CI to enforce it.

### Step 6: Generate Tests

```text
Write bun:test tests for src/app.ts. Cover validation errors, duplicate registration, wrong password,
missing or invalid tokens, and that a private project is hidden from other callers.
```

`test-generator` reads the routes, detects the framework from `package.json` (Bun's built-in `bun:test` here), and calls `app.handle(new Request(...))`, so no network port is needed. Run the tests against a throwaway Postgres whose `DATABASE_URL` points at it, never a shared database.

```typescript
// test/api.test.ts (excerpt)
import { describe, expect, it } from "bun:test";
import { app } from "../src/app";

const call = (path: string, init: RequestInit = {}) => app.handle(new Request(`http://localhost${path}`, init));
const post = (body: unknown, headers: Record<string, string> = {}) => ({
  method: "POST", headers: { "content-type": "application/json", ...headers }, body: JSON.stringify(body),
});

describe("projects", () => {
  it("rejects a non-uuid id", async () => {
    expect((await call("/projects/not-a-uuid")).status).toBe(422);
  });

  it("hides a private project from everyone but its owner", async () => {
    const email = `user-${crypto.randomUUID()}@example.com`;
    const reg = await call("/auth/register", post({ email, name: "Test User", password: "correct horse battery" }));
    const auth = { authorization: `Bearer ${(await reg.json()).token}` };
    const { id } = await (await call("/projects", post({ name: "secret" }, auth))).json();
    expect((await call(`/projects/${id}`)).status).toBe(404);
    expect((await call(`/projects/${id}`, { headers: auth })).status).toBe(200);
  });
});
```

## The Outcome

Juri's API has a single type chain from database to client, all inferred. The Drizzle schema defines the shape of the data, Elysia handlers use it and validate input with TypeBox, and Eden Treaty reads the Elysia app type to give the client typed calls.

When Juri adds a column to `projects`, the chain follows: edit the schema, run `drizzle-kit generate` and `migrate`, and the API returns the new field and the client autocompletes it. When Juri removes a field, every client use of it fails type-checking. No OpenAPI spec to update, no type packages to publish, no codegen step. The OpenAPI plugin still serves interactive docs at `/openapi`, generated from the same route schemas.

## Related Skills

- **elysia**: routes, TypeBox validation, `resolve`-based auth, `status()` responses, the OpenAPI plugin and Eden Treaty.
- **drizzle-orm**: schema, relations, inferred types, the `db.query` relational API and drizzle-kit migrations.
- **test-generator**: generates the `bun:test` suite for the routes, including validation and access-control cases.
